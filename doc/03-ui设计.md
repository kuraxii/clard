# Clard 完整代理管理工具 — UI 设计

> 版本：v0.2（设计稿） · 目标平台：Linux · 界面：TUI（ratatui） · 状态：待评审
> 与 `01-方案设计.md`（v0.2：TUN-only + `clard-helper` 常驻）、`02-交互设计.md` 配套。
>
> UI 不再出现「系统代理」概念：数据面只有 TUN（+ 可选的手动混合端口）。

## 1. 全局框架

每个页面共用四段式骨架，内容区按页面替换：

```
┌────────────────────────────────────────────────────────────────────────┐
│ ① 顶栏 Header（3 行）                                                  │
│    Clard · helper: 已连接 · 核心: Running · TUN: 开 · 配置: 订阅A      │
├────────────────────────────────────────────────────────────────────────┤
│ ② 导航 Nav（1 行）                                                     │
│    [1 主页] [2 配置] [3 代理] [4 连接] [5 日志] [6 设置]               │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│  ③ 内容 Content（可滚动，Min 高度）                                    │
│      · 列表 / 树 / 表格 / 表单 / 日志                                  │
│                                                                        │
├────────────────────────────────────────────────────────────────────────┤
│ ④ 页脚 Footer（2 行）                                                  │
│    帮助键提示行：↑↓移动 · Enter确认 · q退出 · ?帮助                    │
│    消息条：最近一条 成功/警告/错误                                     │
└────────────────────────────────────────────────────────────────────────┘
```

- 终端 **最小尺寸**：80×24；小于该值显示居中提示「请放大终端」，不渲染内容。
- 内容区用 `Constraint::Min(0)` 自适应；列表超出可滚动，右侧显示滚动条。

## 2. 配色主题

暗色为默认（亮色为反相变体），语义色全站一致：

| 角色 | 颜色（256 色） | 用途 |
|---|---|---|
| 背景 | `#1e1e2e` / 亮色 `#f5f5f5` | 全屏底 |
| 面板 | `#2a2a3a` / `#ffffff` | 卡片、列表底色 |
| 边框 | `#45475a` | 区块边框 |
| 主文字 | `#cdd6f4` / `#333` | 正文 |
| 次级文字 | `#6c7086` | 说明、提示 |
| 强调色 | `#89b4fa`（蓝） | 选中、焦点、当前项 |
| 成功 | `#a6e3a1`（绿） | Running、开、成功 |
| 警告 | `#f9e2af`（黄） | 更新中、降级 |
| 错误 | `#f38ba8`（红） | 失败、致命 |
| 高亮强调 | `#cba6f7`（紫） | 数字、延迟值、速率 |

- 选中项：强调色文字 + 深一档背景（`#313244`）。
- 状态色语义统一：**绿=开/成功，灰=关/停止，黄=进行中/能力受限，红=失败/Degraded**，贯穿 Header 与各页，不做歧义。
- `helper: 不可达/未安装`、`核心: Degraded（已 fail-open 恢复直连）` 用红色，并在页脚消息条常驻提示，不依赖用户主动进日志页。

## 3. 各页面 UI

### 3.1 主页（Home）

```
┌─ 核心状态 ──────────────────────────────────────┐
│  状态: ● Running        PID: 1234               │
│  核心: mihomo 1.19.2    重启: 0 次              │
│  混合端口: 7890 (仅 127.0.0.1)                  │
└─────────────────────────────────────────────────┘
┌─ TUN ─────────────────┐ ┌─ 当前配置 ────────────┐
│  ● 开 · device clard0 │ │  名称: 订阅A (remote) │
│  tbl 2023 · rule 9100 │ │  上次更新: 2 小时前   │
│  校验: ✓ 路由/规则    │ │  下次更新: 22 小时后  │
└───────────────────────┘ └───────────────────────┘
┌─ 流量 ──────────────────────────────────────────┐
│  上行: 12.3 KB/s   下行: 456.7 KB/s             │
│  累计 ↑1.2GB ↓34.5GB  出口: 节点A               │
└─────────────────────────────────────────────────┘
```

卡片式布局，四张卡片 2×2 网格；页脚提示 `s/S` 启停核心、`t` 切 TUN、`D` 紧急恢复直连（`cleanup-tun`）、`i` 安装后台服务（仅未安装时）。

- TUN 卡在能力不足时显示灰色 `○ 关` + 红色 reason 行（如「无 /dev/net/tun（容器）」），并提示手动模式退路。
- Degraded 时核心状态卡红框 + 显示「已 fail-open 恢复直连，`s` 重试」。

### 3.2 配置文件（Profiles）

左右分栏，左列表右详情：

```
┌ 配置文件列表 (3) ────────────┐ ┌ 详情 ──────────────────────┐
│  ▸ ● 订阅A         更新中…   │ │ 名称: 订阅A                 │
│     订阅B          ✓ 刚刚    │ │ 类型: remote                │
│     本地配置       ✓ 3 天前  │ │ URL:  https://…/sub        │
│     订阅C          ✗ 失败    │ │ 流量: 已用 5G / 总量 100G   │
│                              │ │ 到期: 2026-01-01           │
│  [a新增] [i导入] [u更新]     │ │ 更新间隔: 1440 分钟          │
│  [e选项] [d删除] [o打开]     │ │ 自动更新: ● 开              │
└──────────────────────────────┘ └────────────────────────────┘
```

- 行前缀：`●` 当前配置；`✓` 最近更新成功；`✗` 上次失败；spinner 更新中。
- 列表尾部常驻操作按钮栏（`a i u e d o`），与键位一致。

### 3.3 代理（Proxies）

分组树，左树右节点（或折叠式单栏，按宽度自适应）：

```
┌ 分组 ──────────────────────────┐ ┌ 节点 (Proxy 组) ──────────┐
│  ▾ ● Proxy        [自动]  132ms │ │  ▸ 节点A        132 ms   │
│    ▸ 节点A · 节点B · 节点C       │ │    节点B         88 ms   │
│  ▸ Netflix        [自动]  210ms │ │    节点C       超时       │
│  ▸ YouTube        [手动]  —     │ │    节点D        105 ms   │
│  ▾ Fallback       [手动] 节点A  │ │  [t测当前] [T全测]        │
└────────────────────────────────┘ └──────────────────────────┘
```

- `▸/▾` 折叠态；`●` 当前分组；`[自动]/[手动]` 分组选择来源；右侧延迟数值。
- 节点行前缀 `▸` 表示当前选中节点；延迟颜色：<100ms 绿、<300ms 黄、超时红。
- 底部操作栏 `t/T/d/s/f`。

### 3.4 连接（Connections）

表格 + 顶部流量仪表：

```
┌ 流量: ↑ 12.3KB/s ↓ 456.7KB/s · 连接数 48 ──────────────┐
├ 来源                    目标              规则    延迟   收发 ┤
│ ▸ 192.168.1.5:52000  →  104.16.x.x:443   Proxy  132ms ↑2.1↓8.3│
│   192.168.1.5:52001  →  8.8.8.8:53       DIRECT 1ms  ↑0.1↓0.1│
│   …                                                         │
└────────────────────────────────────────────────────────────┘
  排序:u/d · x关闭 · X全关 · c单位 · r刷新
```

- 表格列宽：来源 24、目标 24、规则 8、延迟 7、收发 16。
- 规则列着色：`DIRECT` 灰、`Proxy` 蓝、`REJECT` 红。

### 3.5 日志（Logs）

分页签 + 可滚动日志行：

```
┌ [应用] [核心] [审计] [合并]  级别:info · 跟随:● ─────────────┐
│ 09:12:01 [Info ] [Core  ] 核心已启动 pid=1234                │
│ 09:12:02 [Info ] [Config] 已切换到配置 订阅A                 │
│ 09:12:03 [Warn ] [Timer ] 订阅B 更新失败：timeout            │
│ 09:12:04 [Info ] [Audit ] tun.enable uid=1000 → ok           │
│ 09:12:09 [Error] [Audit ] config.apply → reject              │
│ …                                                            │
└──────────────────────────────────────────────────────────────┘
  e级别 · f过滤 · F跟随 · c清空 · G末尾
  审计栏:o按op过滤 · Enter展开 · I切intent/result · x导出
```

- 行格式：`HH:MM:SS [级别] [来源] 消息`，级别四色（error 红 / warn 黄 / info 蓝 / debug 灰）。
- 审计行格式：`HH:MM:SS [级别] [Audit ] <op> uid=<uid> pid=<pid> → <result>`；`Enter` 展开显示同一 `op_id` 的 intent/result 配对、`auth` 方式、`cfg_sha256` 与字段级 diff、`net` 前后快照（device/table/rule/默认路由）、`err`。
- 审计内容**不包含**订阅凭据与节点密码（只显示字段名与哈希）。
- 顶部页签高亮当前视图；跟随模式时新行自动滚到底，手动上滚即解除。

### 3.6 设置（Settings）

左侧设置项 + 右侧值（或页签式，按实现取舍）：

```
┌ [通用] [TUN与旁路] [核心] [后台服务] [日志] [审计] [关于] ─┐
│                                                            │
│   混合端口:            7890 (仅127.0.0.1)   ↻              │
│   允许局域网连接:       ○ 关                  !            │
│   TUN:                 ● 开                  ↻             │
│   TUN stack:           [system]              ↻             │
│   旁路(route-exclude):  10/8,172.16/12,…      ↻            │
│   exclude-uid:         (空)                  ↻             │
│   strict-route:        ○ 关 风险:残留即断网    !           │
│   auto-redirect:       ○ 关 风险:nft残留       !           │
│   …                                                        │
│                                                            │
│  ↑↓选择 · Enter修改 · ↻=热重载生效 · !=需二次确认          │
└────────────────────────────────────────────────────────────┘
```

- 布尔项 `●/○`；枚举项 `[值]` 循环切换；数字项弹出输入框；列表项（旁路网段 / exclude-uid / exclude-interface）进多行编辑弹窗。
- **`↻` = 经 IPC 热重载生效**（`PATCH /configs` 内联 payload），常规项不再需要重启核心；只有核心升级会重启。
- **`!` = 危险项**（`strict-route`、`auto-redirect`、局域网共享、卸载服务、变更授权）：二次确认 + 展示风险文案（引用 `01-方案设计.md` §6.3/§6.4）。
- **后台服务页签**：helper 版本与状态、`clard-helper.service` 单元状态、授权 uid（只读）、偏执模式（polkit 二次授权，默认关），以及 `[i 安装] [u 卸载] [a 变更授权]` —— 三者先展示将执行的 `pkexec`/`sudo` 命令，确认后退出 raw mode 执行，完成后重进 TUI。
- **关于页签**：版本、`clard-proto` 协议版本、路径一览（XDG / `/run/clard` / `/var/log/clard` / `/etc/clard`）。

## 4. 通用组件规格

| 组件 | 规格 |
|---|---|
| 列表 | 行高 1，选中反色，右侧滚动条，空态居中「(空)」 |
| 表格 | 表头粗体+分隔线，列宽固定，单元格溢出截断加 `…` |
| 弹窗 | 居中，宽 ≤ 内容+4，遮罩半透明，标题栏 + 内容 + 按钮行 |
| 输入框 | 单行，光标闪烁，`Ctrl+u` 清行 |
| spinner | `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` 每秒 10 帧，用于「更新中/切换中/测试中」 |
| 消息条 | 右对齐，成功绿/警告黄/错误红，5 秒淡出 |

## 5. 尺寸与响应式

| 宽度 | 行为 |
|---|---|
| < 80 列 | 显示「请放大终端」，不渲染 |
| 80–110 列 | 分栏页压缩详情栏宽度，列表优先 |
| > 110 列 | 全部分栏展开 |

高度不足 24 行同样提示；内容区在两者之间自适应收缩。

## 6. 主题扩展点

- 颜色集中于 `theme` 模块（现 `canvas.rs` 的 `Theme::current()` 保留并重构），支持「暗/亮」一键切换。
- 后续可读取 `clard.toml` 的 `[theme]` 段做自定义配色，键位集中 `keymap` 模块。
