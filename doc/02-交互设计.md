# Clard 完整代理管理工具 — 交互设计

> 版本：v0.2（设计稿） · 目标平台：Linux · 界面：TUI · 状态：待评审
> 与 `01-方案设计.md`（TUN-only + `clard-helper` 常驻）配套，键位与页面结构对应 `03-ui设计.md`。
>
> **前提**：后台服务 `clard-helper`（root，systemd 系统单元）是**系统级服务、不分用户**，拥有核心、TUN 与全部数据（/var）；TUI 只是客户端，**退出/崩溃/多开都不影响后台代理**，且全程不需要 su。

## 1. 设计原则

1. **键盘优先，鼠标为辅**：所有高频操作必须有单键/组合键直达，鼠标点击为可选增强。
2. **即时反馈**：任何命令（切换、更新、测试）立即给出「进行中 → 成功/失败」反馈，不静默。
3. **不丢状态**：切换页面不重置列表滚动位置与选中项；错误只提示不阻塞。
4. **危险操作需确认**：删除配置、关闭全部连接、卸载服务等破坏性动作二次确认。
5. **可发现性**：页脚常驻快捷键提示；`?` 打开全局帮助。

## 2. 全局导航模型

### 2.1 页面（状态机）

```
┌─────────┐  1  ┌───────────┐  2  ┌──────────┐  3  ┌─────────────┐
│ 主页     │────▶│ 配置文件   │────▶│ 代理      │────▶│ 连接         │
│ Home    │     │ Profiles  │     │ Proxies  │     │ Connections │
└─────────┘     └───────────┘     └──────────┘     └─────────────┘
     ▲                                                      │
     │       5  ┌──────────┐  4  ┌──────────┐               │
     └──────────│ 设置      │◀────│ 日志      │◀──────────────┘
                │ Settings  │     │ Logs      │
                └──────────┘     └──────────┘
```

- 页面用 `1..6` 数字直达，`Tab` 进入内容区、`Esc` 返回/退出（见各页）。
- 页面间切换**保留**各自内部状态（选中行、滚动、过滤条件）。

### 2.2 全局键位（默认）

| 键 | 作用 | 备注 |
|---|---|---|
| `1`–`6` | 直达对应页面 | 主页/配置/代理/连接/日志/设置 |
| `↑` `↓` / `j` `k` | 列表上下移动 | 全页通用 |
| `←` `→` / `h` `l` | 左右面板切换 / 树展开收起 | 分栏页 |
| `Enter` | 确认 / 进入 / 触发主操作 | |
| `Tab` | 聚焦下一区域 / 切换页签 | |
| `Esc` | 返回上一层 / 关闭弹窗；主页时为退出 | |
| `q` | 退出（主页/弹窗外任意处） | 有未完成任务时确认 |
| `?` | 全局帮助浮层 | 任意页 |
| `Ctrl+c` | 强制退出（兜底） | TUI 退出不影响后台核心与 TUN；要停代理请用 `S`（停核心）或 `D`（紧急恢复直连） |

### 2.3 弹窗与确认

- **确认弹窗**：`Enter`=确认，`Esc`=取消，默认焦点在「取消」。
- **输入弹窗**（如订阅 URL、搜索）：单行输入，支持 `Ctrl+u` 清行、`Backspace` 删字符、`Enter` 提交、`Esc` 取消。
- **帮助浮层**：全屏半透明遮罩 + 键位表，`?`/`Esc` 关闭。

## 3. 页面交互

### 3.1 主页（Home / `1`）

**用途**：一屏总览，不承载复杂操作。

| 区域 | 展示 | 交互 |
|---|---|---|
| 后台服务 | helper 连接状态（已连接 / 不可达 / 未安装）+ 版本 | `Enter` 查看详情；未安装时 `i` 安装（pkexec，仅一次） |
| 核心状态 | Running/Starting/Stopped/**Degraded** + PID + 重启次数 + 核心版本 | `s` 启动/重启，`S` 停止（确认） |
| TUN | 开/关 + 生效校验（device `clard0` / table 2023 / rule 9100）+ 不可用原因 | `t` 切换（确认后热重载），`D` 紧急恢复直连（`cleanup-tun`，确认） |
| 当前配置 | 名称、类型、上次更新 | `Enter` 跳到 Profiles 页 |
| 流量摘要 | 上/下行速率与总量、当前出口线路 | 只读 |

### 3.2 配置文件（Profiles / `2`）

**用途**：配置文件全生命周期管理。

**列表视图**（默认焦点在列表）：

| 键 | 动作 | 反馈 |
|---|---|---|
| `↑↓/jk` | 移动选中 | 高亮行 |
| `Enter` | 切换为当前配置 | 状态行「切换中…」→「已切换/失败」 |
| `a` | 新增本地文件 | 文件选择弹窗 |
| `i` | 从 URL 导入 | 输入 URL（+可选名称/间隔） |
| `u` | 立即更新选中订阅 | 行内「更新中…」spinner |
| `e` | 编辑选项（间隔/UA/走代理） | 表单弹窗 |
| `d` | 删除 | 确认弹窗 |
| `r` | 重命名 | 输入弹窗 |
| `o` | 打开本地文件（`$EDITOR`） | 外部进程，返回后提示 |

**详情面板**（右侧，`l` 聚焦）：显示 uid、类型、URL、流量/到期、上次/下次更新、自动更新开关。

**规则**：`Enter` 切换时若核心未运行，自动先启动核心再切换；删除「当前」配置时自动选中下一个并切换。

### 3.3 代理（Proxies / `3`）

**用途**：查看分组树、选择节点、测延迟。

**树视图**（左右两栏）：

| 键 | 动作 |
|---|---|
| `↑↓/jk` | 上下移动 |
| `←→/hl` | 折叠/展开分组，或左右栏切换 |
| `Enter` | 选中分组内高亮节点（下发 `select_node_for_group`） |
| `t` | 对当前节点/分组测延迟 |
| `T` | 全部分组测延迟 |
| `d` | 清除该分组的固定选择（回退 URLTest 自动） |
| `s` | 按名称/延迟/类型排序 |
| `f` | 过滤（输入关键字） |

**反馈**：选中节点后分组 `now` 立即更新；延迟测试显示「…ms」或「超时」。

### 3.4 连接（Connections / `4`）

**用途**：查看活跃连接与实时流量。

| 键 | 动作 |
|---|---|
| `↑↓/jk` | 移动选中连接 |
| `u` / `d` | 按上行 / 下行排序 |
| `x` | 关闭选中连接 |
| `X` | 关闭全部连接（确认） |
| `c` | 切换「实时流量」显示单位（KB/s ⇄ 总量） |
| `r` | 手动刷新列表 |

**流量订阅**：进入本页自动订阅 `traffic` WebSocket，离开停止。

### 3.5 日志（Logs / `5`）

**用途**：应用 / 核心 / **审计** 三类日志查看与诊断。

| 键 | 动作 |
|---|---|
| `Tab` | 循环切换 应用日志 / 核心日志 / 审计 / 合并视图 |
| `↑↓/jk` | 滚动（跟随尾部时先解除跟随） |
| `e` | 级别过滤（循环 error→warn→info→debug） |
| `f` | 关键字过滤（输入） |
| `F` | 跟随/取消跟随尾部 |
| `c` | 清空当前视图 |
| `G` | 跳到末尾 |

**审计栏专属**：`o` 按 op 过滤（`tun.enable` / `config.apply` / `core.crash` / `watchdog.failopen` / `cleanup.tun` / `policy.reject` / `rpc.error` …）、`Enter` 展开单条详情（actor uid/pid、auth 方式、`cfg_sha256` 与字段级 diff、net 前后快照、err）、`x` 导出当前过滤结果到用户指定目录（如 `~/Downloads`）、`I` 切换只看 intent / 只看 result / 全部（同一 `op_id` 配对显示）。

### 3.6 设置（Settings / `6`）

**用途**：全局设置，分页签。

| 页签 | 配置项 | 交互 |
|---|---|---|
| 通用 | 混合端口（仅 127.0.0.1）、局域网共享（默认关）、主题/键位 | 选项式 `Enter` 切换 / 数字输入 |
| TUN 与旁路 | TUN 开关、stack、dns-hijack、`route-exclude-address`（默认预置私网段）、`exclude-uid`、`exclude-interface`、`exclude-dst-port`；`strict-route` / `auto-redirect`（**默认禁用**，开启需二次确认 + 风险提示） | 开关后立即热重载并**读回校验**（`GET /configs` + `ip link`/`ip rule`），未生效则回退设置并报错 |
| 核心 | 当前版本/checksum、检查更新、下载并升级（TUI 下载校验 → helper 复核哈希 → 原子替换 `/usr/libexec/clard/mihomo`） | 按钮式 `Enter`；升级需确认（会短暂重启核心） |
| 后台服务 | helper 状态/版本、systemd 单元状态、偏执模式（TUN 开关额外走 polkit，默认关） | `i` 安装、`u` 卸载 —— 都会提示需要的 `sudo`/`pkexec` 命令并退出 TUI 界面执行 |
| 日志 | 级别、文件大小、保留数量 | 选项式 |
| 审计 | 保留大小/份数、是否双写 journald、导出目录 | 选项式（改动写 `helper.toml`，需 root → 提示命令） |
| 关于 | 版本、协议版本、路径一览（`/run/clard` / `/var/lib/clard` / `/var/cache/clard` / `/var/log/clard` / `/etc/clard`） | 只读 |

**规则**：设置改动经 IPC 由 helper 写盘（`/var/lib/clard/clard.toml`）；涉及 TUN/端口/DNS 的改动经 IPC 下发并**热重载**（`PUT /configs` 内联 payload），通常无需重启核心；被 helper 策略校验拒绝时，消息条给出原因并在审计里留 `policy.reject`。需要改 `/etc/clard/helper.toml` 的项一律提示命令，不由 TUI 直接写。

## 4. 状态与错误反馈

统一用三种通道反馈，避免信息丢失：

1. **页脚消息条**：最近一条结果（成功/失败 + 原因），5 秒后淡出，`m` 查看历史。
2. **行内状态**：列表项的实时状态（更新中 spinner、延迟值、错误标记）。
3. **日志页**：所有可诊断细节沉淀到日志，消息条只给结论。

错误分级：

| 级别 | 展示 | 例 |
|---|---|---|
| 提示 info | 页脚灰字 | 「配置已切换」 |
| 警告 warn | 页脚黄字 | 「订阅更新失败，保留旧文件」 |
| 错误 error | 页脚红字 + 日志 | 「核心启动失败：端口被占用」 |
| 致命 fatal | 弹窗 + 停止操作 | 「配置文件非法，无法生成运行时配置」、「helper 不可达：后台服务未运行（`systemctl status clard-helper`）」、「核心反复崩溃，已 fail-open 恢复直连」 |

## 5. 典型任务流

### 5.1 首次使用（导入并启动）

```
启动 → 主页提示「后台服务未安装」→ 6 设置 → 后台服务 → i 安装
     （pkexec 授权一次；安装期间退出 TUI 界面，完成后重进）
     → helper Running · 已连接 → 2 进 Profiles → i 输入订阅 URL → Enter 导入
     → Enter 切换 → helper 自动启动核心 → 主页 Running + 当前配置
     → 6 设置 → TUN 与旁路 → TUN 开 → 热重载 + 回读校验通过
     → 主页确认「TUN: 开 · clard0 · table 2023」→ 完成
     → 关掉 TUI：代理照常工作（helper 常驻，systemd 监督）
```

### 5.2 TUN 开不起来（能力不足）

```
6 设置 → TUN 与旁路 → t 开 → 能力探测失败
  → 给出结构化 reason：无 /dev/net/tun（容器/WSL1）· 无 CAP_NET_ADMIN ·
     clard0 或 table 2023 / rule 9100 被占用 · 缺 iproute2 · 核心未安装/校验失败
  → TUN 保持「关」，设置不被静默修改；提示退路：手动模式（应用自填 127.0.0.1:7890）
```

### 5.3 排查断网

```
主页 D 紧急恢复直连（幂等 cleanup-tun：删 rule 9100..9110 → flush table 2023 → 删 clard0 → 校验）
     → 网络立即恢复
5 日志 → Tab 到「审计」→ o 过滤 op=tun.enable / watchdog.failopen / cleanup.tun / core.crash
     → Enter 展开：actor uid/pid、cfg_sha256 与字段级 diff、net 前后快照、err
     → Tab 到「核心」→ e 过滤 error → 定位根因
主页 Degraded（核心反复崩溃、watchdog 已放弃）→ 按提示 s 重试 或 S 停止后再排查
```

### 5.4 后台服务不可达

```
启动 → 连接 helper.sock 失败
     → 全屏提示「后台服务不可达：未安装或未运行（systemctl status clard-helper）」
     → 提供：i 安装（pkexec，仅一次）/ 查看帮助 / 退出
     → 安装完成后重进；若已安装则排查 systemd 状态
```

## 6. 无障碍与可配置

- 键位集中定义在 `clard-tui` 的 keymap 模块，后续支持自定义键位文件。
- 颜色方案支持亮/暗，设置页切换（配 `03-ui设计.md`）。
- 所有交互文案中文，后续可抽离 i18n。
